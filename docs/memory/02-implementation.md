# 记忆系统实现说明

当前记忆链路分为四层，但不是四套系统。

## L1：启动摘要

`MEMORY.md` 是唯一会稳定拼接到模型上下文前面的长期记忆摘要。它不保存原始会话，也不罗列完整文件清单，只提供：

- 角色定位。
- 用户长期偏好摘要。
- L2 当前主题。
- L3 SOP 当前主题。
- 检索入口。

L1 会随着 L2/L3 变化自动重写，并保持短小。

## L2：长期事实

`facts/` 保存用户长期偏好、身份、稳定配置和可跨会话复用的事实。L2 文件需要有来源信息，避免无法解释“为什么记住了这条”。

## L3：SOP 和 Skills

`sops/` 保存可复用流程。`sops/skills/` 保存 claude-yh 专属 Skill。

SOP 和 Skill 二选一：

- 适合模型主动调用、带触发条件和操作步骤的能力写成 Skill。
- 普通经验、排障步骤、项目流程写成 SOP。

同一件事不能同时保存一份 SOP 和一份 Skill。

## L4：会话归档

`sessions/` 保存会话摘要和证据来源。L4 不直接污染 L1/L2/L3。只有经过模型抽取并符合长期价值的内容才会提升到 L2/L3。

## 自动整理流程

1. 会话关闭、切换、应用退出或空闲触发整理。
2. 判断该 session 是否有变化。
3. 生成或更新 L4 摘要。
4. 主模型判断是否有 L2/L3 候选。
5. 合格候选写入 L2/L3。
6. 如果 L2/L3 有变化，重写 L1。
7. 写入诊断日志。

## 不再使用向量数据库

当前实现删除了向量数据库路径，L2/L3 使用关键词检索和直接文件读取。这样更简单、可解释，也避免 embedding provider、索引一致性和 FAISS 存储维护成本。
