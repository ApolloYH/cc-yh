# 记忆系统使用指南

claude-yh 只维护一套长期记忆。原有 memory 机制仍是主系统，L1-L4 是在它上面的结构化增强层。

## 存储位置

全局记忆位于：

```text
~/.claude-yh/memory/
  MEMORY.md        # L1，发给模型的压缩摘要
  facts/           # L2，长期事实、偏好、角色定位、稳定规则
  sops/            # L3，可复用 SOP
  sops/skills/     # claude-yh 专属 Skills
  sessions/        # L4，会话摘要和溯源证据
```

项目会话仍保存在：

```text
~/.claude-yh/projects/
```

## 更新策略

- 普通聊天期间不每轮完整抽取。
- 会话关闭、切换会话、应用退出或长时间空闲后，基于整个会话增量整理一次。
- 如果 L4 摘要已经比原始会话新，就跳过重复抽取。
- 只有 L2/L3 真正变化时才重写 L1。
- L1 有硬限制，只写角色定位、用户长期偏好摘要、L2 主题、L3 SOP 主题和检索入口。
- Skill 有独立 discovery/listing 入口，不再写进 L1。

## 沉淀规则

L2 只保存长期稳定信息，例如：

- 用户明确表达的长期偏好。
- 身份、角色定位和稳定约束。
- 重要配置、路径、模型偏好。
- 可跨会话复用的事实。

L3 只保存抽象流程，不保存一次性任务结果：

- 可复用排障流程。
- 可复用浏览器操作流程。
- 可复用开发、测试、发布流程。

一次性搜索结果、天气、热榜、临时问题不会进入 L2/L3，只会作为 L4 归档。

## 溯源

新写入的 L2/L3 文件会保留来源信息，指向对应 L4 或原始 session JSONL。需要追溯时，先看 L2/L3 文件中的 `Source` 字段，再回到 `sessions/` 或 `projects/` 查证。

## 查看和编辑

- CLI 可以通过记忆相关命令查看。
- Web/桌面端设置里的“记忆”页面可以查看 L1-L4。
- 记忆更新记录会写入诊断日志，方便确认是否抽取、跳过或写入。
