# claude-yh 记忆系统

claude-yh 的记忆系统不是另起一套替代原始机制，而是在原有长期记忆基础上增加 L1-L4 分层、自动整理、可溯源归档和 Skill/SOP 沉淀。目标是让新会话能带上必要背景，同时避免把历史聊天原文直接塞进上下文。

## 当前设计

| 层级 | 作用 | 存储位置 |
| ---- | ---- | ---- |
| L1 | 每次会话注入的极短长期摘要，只写角色定位、长期偏好、L2/L3 主题和检索入口 | `~/.claude-yh/memory/MEMORY.md` |
| L2 | 稳定事实、偏好、配置约束、长期规则 | `~/.claude-yh/memory/facts/` |
| L3 SOP | 可复用但不适合做成模型 Skill 的流程经验 | `~/.claude-yh/memory/sops/` |
| L3 Skill | claude-yh 专属技能，走 Skill discovery/listing，不再重复写入 L1 | `~/.claude-yh/memory/sops/skills/` |
| L4 | 会话摘要、证据和溯源归档 | `~/.claude-yh/memory/sessions/` |

## 更新策略

- 普通聊天过程中不每轮跑完整抽取。
- 会话关闭、切换会话、应用退出、长时间空闲后统一整理一次。
- L4 只对发生变化的会话增量生成摘要；已经比原始会话新的摘要会跳过。
- L2/L3 由模型判断是否值得沉淀，不能把一次性搜索、临时问答、无复用价值的请求写成事实或 SOP。
- L1 只在 L2/L3 真实变化后重写，并有硬限制：只保留短摘要和相对路径入口。
- 不再维护向量库；L2/L3 使用关键词检索和按需读取，避免额外索引复杂度。

## 自动沉淀规则

记忆抽取由主模型/抽取模型根据提示词完成，不靠正则把对话标题硬写入记忆。

- 用户明确长期偏好、身份定位、稳定配置和规则，才进入 L2。
- 可复用排障流程、项目通用操作步骤，进入 L3 SOP。
- 能被模型主动调用、带清晰触发条件和执行步骤的能力，进入 L3 Skill。
- 同一件事不能同时写 SOP 和 Skill；更适合被模型主动调用时优先写 Skill。
- L4 是证据来源，不能直接污染 L1/L2/L3。

## 在界面中查看

桌面端和 Web 端的设置页提供“记忆”选项，可以查看：

- L1 当前注入摘要
- L2 facts
- L3 SOP 和 Skills
- L4 会话归档
- 记忆更新记录，包括整理原因、会话标题、模型判断、写入结果和跳过原因

CLI 端可以通过 `/memory` 查看和管理同一套全局记忆。

## 日志与溯源

新数据会写入诊断日志和 L4 摘要，便于确认某条 L2/L3 记忆从哪个会话来：

- 诊断日志：`~/.claude-yh/logs/diagnostics/*.jsonl`
- L4 摘要：`~/.claude-yh/memory/sessions/`
- L2/L3 文件内部包含来源会话、创建时间、修改时间和 source 路径

## 与旧机制的关系

旧机制的核心价值是“长期记忆自动化”。claude-yh 保留这一点，但把写入边界收紧：

- 主对话不直接随意写 `~/.claude-yh/memory`。
- 会话结束后统一抽取，降低频率和噪声。
- L1 不再罗列文件清单，不保存原始聊天。
- L2/L3/L4 各司其职，保证长期记忆可读、可控、可追溯。
